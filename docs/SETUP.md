# Подключение CR Reserve

## 1. Размещение приложения

Создайте аккаунт Cloudflare, если его нет. В **Workers & Pages → Create → Import a repository** подключите `Aleresa/CR_Reserve` как Worker. Команда развёртывания — `npx wrangler@4 deploy`. Отдельная команда сборки не нужна.

Альтернатива с компьютера (Node.js 24):

```sh
git clone https://github.com/Aleresa/CR_Reserve.git
cd CR_Reserve
npx wrangler@4 login
npm test
npm run deploy
```

Запишите фактический HTTPS-адрес Worker. База создаётся из `wrangler.jsonc`; доступные лимиты и тариф уточните в своём аккаунте Cloudflare. Перед платным тарифом оцените условия самостоятельно.

## 2. Секретные настройки

В Worker → Settings → Variables and Secrets добавьте **Secrets**:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | Токен именно @CR_Reserve_Bot из BotFather |
| `ADMIN_IDS` | Ваш числовой Telegram ID; несколько — через запятую |
| `RESERVATION_CHAT_ID` | ID рабочего канала вида -100… или его @username |
| `WEBHOOK_SECRET` | Необязательно: собственный секрет для ручной настройки webhook |

Не помещайте секреты в GitHub, HTML, сообщения клиентам или снимки экрана.

Получить свой ID можно во вкладке «Мои резервы» внутри приложения. Команда `/id` также доступна после подключения бота. До заполнения ADMIN_IDS никто не имеет доступа к управлению.
Неизвестные секреты можно добавить позже. Приём резервов не откроется без канала.

## 3. Рабочий канал

Создайте канал, добавьте @CR_Reserve_Bot администратором с правом публикации сообщений.
Для публичного канала используйте его `@username` в RESERVATION_CHAT_ID.
Для приватного: после добавления ADMIN_IDS перешлите сообщение из канала боту от вашего аккаунта. Бот ответит числовым ID, если Telegram сохранил источник пересылки.
Канал нужен для уведомлений; подтверждение и отмена выполняются в приложении → Управление → Все резервы.

## 4. Telegram Mini App

В @BotFather измените URL существующего приложения `CR_Reserve` у `@CR_Reserve_Bot` на HTTPS-адрес Worker. Короткая ссылка останется https://t.me/CR_Reserve_Bot/CR_Reserve.

Откройте Mini App → **Управление → Подключить бота → Подключить**. Приложение настроит webhook, команды и кнопку меню. Случайный секрет webhook создаётся на сервере и сохраняется в закрытой базе; он не передаётся в браузер или GitHub. Если задан WEBHOOK_SECRET, используется он. После изменения этого секрета повторите подключение.

Альтернатива с компьютера: скрипт `scripts/setup-bot.mjs` читает `BOT_TOKEN`, `APP_URL`, `WEBHOOK_SECRET` из локального окружения. `APP_URL` — адрес Worker. Не вставляйте токен в URL браузера или аргументы команд. После безопасного ввода переменных выполните:

```sh
node scripts/setup-bot.mjs
```

WEBHOOK_SECRET должен совпадать с секретом Worker. Скрипт не печатает секреты, меняет только webhook, команды и кнопку меню этого бота.

## 5. Менеджеры

Откройте **Управление → Менеджеры**. Добавьте имя для выбора клиентом и действующий Telegram-ник каждого менеджера (`@username`), затем сохраните. Личные имена и ники хранятся в базе приложения, не в GitHub.

Перед отправкой нового резерва клиент обязан выбрать менеджера. Пока список пуст, новые резервы не отправляются. В уведомлении рабочего канала появится строка «Менеджер: Имя @username». Менеджер также отображается в резервах и выгрузке Excel. Изменение или удаление менеджера не меняет уже оформленные резервы.

## 6. Первые поставки

Откройте Mini App своим Telegram-аккаунтом → Управление. Создайте поставки из ваших исходных Excel; реальные файлы не хранятся в GitHub.
Для каждой поставки: «+ Поставка» → загрузить Excel → проверить строки/замечания → заполнить поля → сохранить. Поддерживаются столбцы вашего шаблона: Изображение / Наименование / Артикул / Кол-во / Ед. Изм. / Опт. Листы после первого не импортируются.

Перед открытием клиентам проверьте резерв на 1 шт. с другого Telegram-аккаунта: остаток уменьшился, запись видна в «Мои резервы», сообщение пришло в рабочий канал. Отмените этот резерв и проверьте восстановление остатка. Невозможность получения сообщения исправьте до начала работы.

## Изменение резервов

Клиент открывает **Мои резервы → Изменить**, корректирует количества, добавляет товары той же поставки или ставит 0 для удаления позиции. Изменить можно активный неподтверждённый резерв открытой поставки. Для полного отказа используется отмена. Администратор может менять и подтверждённые резервы через **Все резервы**.

Сохранение атомарно пересчитывает остатки. Увеличение ограничено свободным количеством с учётом своего резерва. Цены ранее выбранных позиций сохраняются; новые товары добавляются по текущей цене. Одновременное редактирование защищено версией резерва, повтор запроса не списывает остаток дважды.

Бот сохраняет ID сообщений и обновляет текст при изменении состава, подтверждении и отмене. Длинные резервы занимают несколько сообщений; лишние части после сокращения очищаются и получают отметку, что больше не используются. При временной ошибке Telegram обновление остаётся в очереди.

Для сообщений, отправленных **до этой версии**, ID неизвестен: первое изменение создаёт новое отслеживаемое сообщение. Если сообщение удалено вручную или Telegram запрещает его редактировать, бот отправляет замену. При редком сбое между успешной отправкой нового сообщения и записью его ID возможен дубликат с тем же номером резерва.

## Обслуживание

Отключённый бот или удалённые права канала оставят сообщения в очереди до восстановления доступа. База сохраняет резерв независимо от отправки уведомления. Текст отправляется повторно через alarm.
Следите за ошибками Worker в Cloudflare. Периодически экспортируйте резервы в XLSX, настройте резервное копирование/восстановление Durable Objects в аккаунте Cloudflare до эксплуатации с большим объёмом данных.
